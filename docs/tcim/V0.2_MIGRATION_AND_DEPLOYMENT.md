## 一、V0.2 是什么（一句话）

把 TCIM 从「五表与确定性流程主导、AI 主要分析和表达」改为
**「AI 基于教师完整资料形成情境理解并规划低风险行动；Ontology 与五表提供专业参考和验证；Orchestrator 完成风险审查与正式提交」**。
不推倒现有模块，而是调整决策中心。

### 新增能力（架构位）
| 能力 | 位置 | Owner | 作用 |
|---|---|---|---|
| **Contextual Belief State** | Shared State `contextual_belief_state`（与 Evidence 并列） | belief_manager | 可撤销情境假设；可表外；不自动升级为 Evidence/评分/能力 |
| **Contextual Teacher Model** | TurnContext 后、Planner 前（派生只读快照） | Context Model Builder | 组织事实/有效 Belief/教师议题为每轮快照 |
| **AI Agent Planner** | Teacher Model 后、Risk Gate 前 | （Proposal）A03 | 比较候选、选绿色 selected_action |
| **Decision/Risk Gate** | Planner 后、ActionPlan 提交前 | Orchestrator 子组件 A04 | 验证/裁决 APPROVE/CLARIFY/REJECT，不重做选择 |
| **Challenge Queue** | A12 | 专业审核 | 表偏离/表外/冲突进 Replay + 审核，不改 Production |

### 新增 AI 调用点（A00-A12，核心）
A00 情境解释/Teacher Model（首问前必选）· A01 语义分析（每轮）· A02 Evidence 更新 ·
A02B Belief 更新 · A03 Planner 选 · A04 Risk Gate · A04E MEDIUM 复核（条件）· A05 RAG ·
A06 Interaction Read（早读）· A07 DialoguePlan · A08 生成 · A09 语义复核（标记）· A12 表异议。

### 运行时序
**首问**：Assessment/Process SAVED → 确定性评分/Prior（Evidence 仍 UNKNOWN/null）→ **A00** ContextInterpretation → Belief 提交 → Teacher Model 快照 → **A03** Planner → **A04** Gate → ActionPlan 提交 → A07 PRDM → A08 生成 → Constraint → 首问。

**教师回应后（双状态链）**：RAW_TURN_SAVED → **A01** 语义 → **A02** Evidence(validator/committer) → **A02B** Belief → Teacher Model 快照 → **A03** Planner → **A04** Gate → ActionPlan → A07 DialoguePlan → A08 生成 → Constraint → 下一问。

**时间红线**：`raw_turn_saved_at < semantic_proposal_at < evidence_or_belief_commit_at < planner_decision_at < action_commit_at < visible_reply_sent_at`。

**Evidence 冻结枚举**：`UNKNOWN/null`、`NOT_DEMONSTRATED/0`、`PARTIAL/1`、`SUFFICIENT/2`、`HIGH_QUALITY/3`（不再 `0/UNKNOWN`）。

## 四、验收清单（部署后、真实验收）

分层验证——因为链路是**失败静默降级**（缺 key/网关/LLM 超时都回退，不报错），所以「没报错」≠「已生效」。要同时看**云函数 fallback 字段 + Replay 的 source**。

### L1 纯逻辑（任何环境）
```bash
node cloudfunctions/gsyg_semanticProbe/semantic_core.test.js
node cloudfunctions/gsyg_planner/planner_core.test.js
node tcim/tests/v2_double_state.test.js && node tcim/tests/v2_planner_gate.test.js
node web/src/core/tcim/engine.test.mjs && node web/src/core/tcim/semantic.test.mjs
```

### L2 云函数本体（控制台测）
- `gsyg_semanticProbe`：传 `{teacherTurn,itemId,anchors}` → 返回 `proposal.slot_evidence_proposals`；`fallback` 为空 = 真通；`semantic_llm_error:` = 查 key/endpoint。
- `gsyg_planner`：传 `{itemId,teacherModel,evidence}` → 返回 `decision.selected_action_id` + `gate.decision`；`fallback` 为空 = 真通。

### L3 网关 + 网页调用（DevTools Network）
- `POST {VITE_WEB_API_BASE_URL}/call` `{action:'semanticProbe'|'planner'}` → `HTTP 200` + `{ok:true,...}`。
- `400 unsupported_action` → 网关未重传；`401` → 会话未建；`502` → 云函数失败。

### L4 语义/规划真的进 Evidence/行动（唯一硬依据）
- Replay 里出现 `SemanticEvent` + `BeliefEvent` + `TeacherModelEvent` + `PlannerEvent` + `GateEvent`；
- **provider/source 非 'offline'/'local'**（说明走了云端而非回退）。若全是 offline/local → 语义/规划层未真正生效。

### 红线检查（必测）
- **打分红线**：LLM 输出无论如何都不改变 `scoring.js` 赋分 + `gsyg_selectFinal` 的 R/P/G 确定性筛题。
- **G05/泄露**：任何 Proposal/question 不出现能力/人格/动机判定词、得分/标准答案/专家排序/评分/R-P/G。
