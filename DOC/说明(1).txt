这个程序在教师完成10个情境排序测验后，先赋分，再结合结果性数据和过程性数据，筛选出适合AI一对一访谈的最终3个情境题。设计目标：R分每人选2题、P-IVI每人选2题、G分每人选2题，最后整合为最终3题。

一、程序实际流程可以分成10步
第1步：读取与校验输入数据
程序要求两个CSV：
一是结果数据，必须包含：
participantName、userOpenid、answers
二是过程日志，必须包含：
userOpenid、questionIndex、timestamp、action
这一步是基础校验，能防止缺少关键字段时继续计算。

第2步：将教师10题排序答案转成得分
程序内置了10道题、24种ABCD排序组合的赋分表。
然后依据内置赋分表得到每道题的最终得分 S_final。这一点符合“10个测验之后进行赋分”的要求。

需要注意：程序假设 answers 中的答案是 0、1、2、3 形式，对应 A、B、C、D。如果平台导出的答案是 1、2、3、4 或直接是 A、B、C、D，这里就需要改。

第3步：计算教师整体水平与每题相对偏离
程序会计算每位教师：
10题平均分
10题总分
每道题得分与个人平均分的差值 RD
RD的绝对值 abs_RD
教师整体水平：总体偏高 / 总体中等 / 总体偏低
其中分类规则是：
平均分 ≥ 3.0：总体偏高
平均分 < 2.0：总体偏低
其余：总体中等

第4步：整理过程日志，并处理题号基准

程序考虑到日志中的 questionIndex 可能是：

0—9
或 1—10

它会自动判断，也允许手动指定：

--log-question-base 0
--log-question-base 1

这一点很重要，可以减少题号错位风险。

第5步：提取过程性行为特征

程序会从日志中提取每题的过程指标，包括：

总用时
首反应用时
首次操作后用时
修改次数
操作次数
首位变化次数
末位变化次数
首末位交换次数
路径回退
路径振荡
疑似中断
重点选项
重点比较选项对

其中超过120秒无操作会被视为可能中断，并对时间进行剔除。这一点符合你之前强调的“过程性数据不能简单等同于停留时长，需要排除外部中断”的思路。

第6步：计算P-IVI过程信息量，并筛选P候选题

程序将过程性指标整合为4类分数：

F_score：首反应异常
M_score：修正投入
B_score：首末位摇摆
O_score：路径振荡

再合成为：

P_IVI = 0.20F + 0.30M + 0.35B + 0.15O

然后每位教师选出2道过程信息量较高的题，作为P候选题。这个设计符合“通过过程数据发现值得访谈的题目”的目的。

第7步：筛选R候选题，即结果性偏离题

R分的逻辑是：

如果教师总体偏高，就找相对低点，用于解释“局部短板”。

如果教师总体偏低，就找相对高点，用于解释“相对优势和可激活能力”。

如果教师总体中等，就找一正一负两个偏离端点，用于解释“能力分化画像”。

这一步很符合访谈目的：不是简单访谈低分题，而是根据教师整体水平寻找最有解释价值的题。

第8步：筛选G候选题，即结果—过程关系题

G分进一步把结果和过程组合起来看。

例如：

结果低 + 过程复杂
结果低 + 过程简单
结果高 + 过程复杂
结果高 + 过程简单

这个设计很好。因为访谈最有价值的不是单纯问“为什么错”，而是区分：

教师是认真比较后仍然判断偏低？
还是快速稳定地形成了偏低判断？
是通过反复权衡形成好判断？
还是已经有稳定专业图式？

这一步对AI访谈很关键。

第9步：生成IIV综合明细

程序还计算了IIV相关指标，包括：

ResultRisk
RelativeDeviation
ProcessConflict
RevisionSignal
TimeSignal
OptionFocus
P_IVI_norm
IIV_classic
IIV_hybrid

这一部分相当于给每道题生成“综合访谈价值”的量化底座。它不直接替代R/P/G筛选，但可以增强研究者解释。这个设计是有价值的。

第10步：整合R/P/G候选题，最终选出3题

最终整合逻辑是：

先把R、P、G候选题合并成候选池。

然后计算：

FES：最终解释强度分
RS：备用综合分

如果某题同时被R/P/G多个来源选中，它会获得更高优先级。

程序还加入了能力类型覆盖修正规则，避免最终3题都集中在同一能力类型上。最终输出每位教师3个访谈题。


二、输出是否符合“教师端不暴露内部计算”的要求？
程序输出两个主要文件：
AI访谈材料.xlsx
研究者筛选材料.xlsx

其中，AI访谈材料只保留：
教师信息
最终题号
情境文本
四个选项
重点选项/重点比较
安全访谈提示词
禁止透露提醒

研究者筛选材料则保留：
最终3题
10题IIV明细
R候选
P候选
G候选
方法说明

这说明程序已经把“AI可用材料”和“研究者内部材料”分开了。程序里还专门提醒：不得向教师透露得分、排名、R/P/G分、IIV或任何评价性结果。

三、需要特别注意的几个问题
1. 答案格式假设需要确认

程序现在假设：
answers里的题号是0—9
选项是0、1、2、3
分别对应A、B、C、D

如果你的小程序实际存储的是1、2、3、4，就会错。这个必须用真实导出数据核对。

2. 过程日志 action 名称需要核对

程序依赖这些日志行为：

enter_question
leave_question
change_sorting_option

如果平台实际日志不是这些名称，比如叫 drag_option、sort_change、submit_answer，那么过程性指标会提取不完整。

3. P候选题在日志缺失时可能不够稳

如果某位教师某题日志缺失，程序仍会根据最终答案生成一条过程记录，但过程信息会很弱。建议正式运行时增加一个字段：

process_data_quality

例如：

完整
部分缺失
严重缺失

这样研究者可以判断P-IVI是否可信。

4. 内置赋分表建议未来外部化

目前赋分表写死在程序中。短期没问题，但后续如果10题版本、题目顺序或赋分方案调整，容易忘记同步修改。建议后续改为读取数据库或Excel赋分表。

5. AI访谈材料不应直接展示给教师

虽然 AI访谈材料.xlsx 已经去掉了大部分内部指标，但仍有：

priorityOption
priorityPair
priorityOptionText
priorityPairText

这些是给AI生成追问用的，不适合原样展示给教师。教师端只需要看到自然语言问题。

四、结论
这个程序的核心流程是成立的，可以概括为：

10题排序作答 → 按24种排序赋分 → 计算个人整体水平与每题偏离 → 提取过程性行为指标 → 生成R/P/G候选题 → 计算IIV辅助解释指标 → 多源整合与能力覆盖修正 → 最终选出3个AI访谈题 → 生成AI安全访谈材料与研究者筛选材料。
要用若干名教师的真实导出数据做一次核查，重点检查：

题号有没有错位；
A/B/C/D转换有没有错位；
日志action名称是否匹配；
最终3题是否符合研究者直觉；
AI访谈材料是否完全不向教师暴露内部评价信息。
