# TCIM Web R6.1 微信发送说明

## 一、研究负责人怎样发送

1. 只发送完整压缩包：`TCIM网页发布交付包_TCIM-WEB-2026.08.30-R6.1.zip`。
2. 不要拆开只发送`dist`、某个源码文件夹或某个Excel文件。
3. 不要另行发送Kimi、OpenAI、腾讯云、GitHub密码，也不要发送任何`.env`文件。
4. 告诉程序员先阅读本文件和`01_程序员发布清单.md`，发布前如有不清楚之处先书面确认。

## 二、这一版究竟是什么

这是已经在研究负责人电脑上验证过的“本机比较版”，发布号为：

`TCIM-WEB-2026.08.30-R6.1`

它的访谈核心是：

`Dialogue Agent主导＋新五表V0.2.1＋Evidence State＋r6对话节律`

当前本机网页故意只连接`http://127.0.0.1:8787`，后台也故意只接受本机回环地址。这样可以保护模型密钥和教师访谈资料，但也意味着：**程序员不能把本机现成的`dist`文件夹直接上传到腾讯云。**

正确发布方式是：

1. 保留本包中的Dialogue Agent、五表、Evidence State和对话节律逻辑；
2. 把Dialogue Agent部署成腾讯云上的受保护后台；
3. 在腾讯云后台配置模型密钥；
4. 让网页通过HTTPS访问该后台；
5. 重新构建网页，再发布静态文件。

这不是重写访谈逻辑，而是把“本机安全外壳”换成“云端安全外壳”。

## 三、包里有什么、没有什么

包内包括：

- 完整Git源码快照；
- 详细交接说明；
- 程序员发布清单；
- 前后端生产变量模板；
- 验收与回滚记录模板；
- 版本清单和文件校验值。

包内故意不包括：

- Kimi/OpenAI密钥；
- 腾讯云或GitHub密码；
- 个人教师访谈记录；
- 本机运行数据；
- `node_modules`、临时日志和缓存；
- 只能连接本机8787端口的现成`dist`。

## 四、发布后请程序员返回什么

请程序员填写并返回`04_发布验收与回滚记录模板.md`，至少包括：正式测试网址、Git提交号、构建时间、健康检查、完整访谈验收、已知问题和回滚方法。

以后每次升级均由研究负责人侧形成新的冻结版本和发布号，程序员按冻结包部署。不得直接在云端静默修改提示词、五表或核心访谈逻辑。
